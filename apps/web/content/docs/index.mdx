RedNest is a GitHub App that reads your code the way an attacker would. It reviews your pull requests, scans whole repositories when you ask, and reports only vulnerabilities it can back with evidence: the way in, the path through your code, a proof of concept, and a fix prompt for your coding agent.

It only ever scans repositories where you have installed it.

## Set up with your agent

The quickest way in. Paste this into Claude Code, Cursor, Codex or any other agent (or press **Set up with your agent** on the home page to copy it):

```text
Set up RedNest for me: it finds exploitable vulnerabilities in my GitHub repositories (https://www.rednest.tech).
Read https://www.rednest.tech/docs/agents.md and follow it. Connect to its MCP server (https://www.rednest.tech/api/mcp) if you can add one, otherwise use its HTTP API with the device flow.
Then call get_me and work through next_steps. Only ask me for what needs me: approving the connection and installing the GitHub App. Do not assume payment or free credits are available.
```

Your agent connects, sets everything up, and can start scans and fix what it finds in your checkout. You step in where a person has to: approving the connection in your browser and choosing repositories on GitHub. Billing and token access are being revised. Once connected, it can do anything the dashboard does: see [Use it from your agent](/docs/agents).

## Or set it up yourself

1. **Sign in with GitHub.** Go to [Get started](/get-started) and press **Continue with GitHub**. RedNest uses your GitHub sign-in to see which repositories you can access.
2. **Install the GitHub App.** From [Repos](/dashboard/repos), choose **Add repositories**, pick the account (yours or an organization) and the repositories RedNest may read. You come back to RedNest when GitHub is done.
3. **Billing for that account.** Hosted access may change; the current product still includes a credits module documented under [Pricing & credits](/docs/pricing). The GitHub account you installed on is the customer. Only an admin of the organization (or the owner of a personal account) can manage billing.
4. **Recon maps each repository.** Once the account is ready to scan, RedNest builds a threat model of every repository: its entry points, trust boundaries, sensitive data and dangerous code. It takes about a minute per repository.
5. **Start scanning.** Open a repository from [Repos](/dashboard/repos) and press **Deep scan** to scan all of it, and open a pull request to see a review. The [Overview](/dashboard) adds up reviews, findings and fixes across every repository, and [Scans](/dashboard/scans) lists every run. Findings appear on the [scan's live feed](/docs/scans#deep-scans) as soon as they survive verification.

From then on pull requests are reviewed automatically (except drafts, some pull requests from forks, and any while the account has no plan or credits; see [PR reviews](/docs/scans#pr-reviews)), and pushes to your default branch check whether open findings have been fixed.

## Where findings show up

- **On the pull request.** A Check called **RedNest** reports what the review found. On private repositories each finding is also posted as a review comment on the vulnerable line. On public repositories, where Checks and comments are visible to everyone, RedNest only posts a count with a link to view the details privately. See [PR reviews](/docs/scans#pr-reviews).
- **In the dashboard.** [Findings](/dashboard/findings) lists everything across your repositories. Each finding has the full attack path, a proof of concept and a fix prompt.
- **By email.** People who have signed in and can push to the repository get an email about new critical findings and finished deep scans. An admin can turn these emails off for the account in [Settings](/dashboard/settings).

## Who can see what

RedNest follows GitHub. You can see a repository's findings, and deep scan it, if GitHub says you have push access or higher. Billing belongs to the GitHub account: organization admins, or the owner of a personal account, can change the plan. There are no separate RedNest invites or roles.
